# Ledger Builder - Stage 1 of V2 Passthrough Feature Acceleration Pipeline

## Overview

The **Ledger Builder** transforms the existing Field Registry (`field_metadata.json`) into a CSV-based **Delivery Ledger** — the single source of truth for tracking the batch delivery of ~70 V2 passthrough features.

This is **Stage 1** of the acceleration pipeline described in `docs/api/acceleration-plan.md`.

## Purpose

The Field Registry contains all HyperFleet API fields with their markers (write-mode, visibility). The ledger **extends** this registry with pipeline-specific columns:

- `feature_ref` - JIRA feature ticket (populated by Stage 3: Test Mapper)
- `test_ref` - Test case reference (populated by Stage 3: Test Mapper)  
- `status` - Delivery status (initial: `needs-classification`)
- `notes` - Manual annotations

## Usage

### Quick Start

```bash
# Set up Python virtual environment and install dependencies
make accel-build-setup

# Build the ledger CSV
make accel-build-ledger

# View pipeline status report
make accel-report

# Output: hack/accelerate/ledger-builder/output/ledger.csv
```

### Manual Usage

```bash
# Activate virtual environment
source hack/accelerate/ledger-builder/.venv/bin/activate

# Run with defaults
python hack/accelerate/ledger-builder/build_ledger.py --verbose

# Custom input/output
python hack/accelerate/ledger-builder/build_ledger.py \
  --input hack/api-codegen/pkg/registry/field_metadata.json \
  --output custom-ledger.csv \
  --verbose
```

### Clean Up

```bash
make accel-build-clean  # Remove venv and generated CSVs
```

## Input: field_metadata.json

The Field Registry at `hack/api-codegen/pkg/registry/field_metadata.json` is generated by `marker-scanner` and contains:

```json
[
  {
    "fieldPath": "spec.deleteProtection",
    "writeMode": "mutable",
    "hidden": false,
    "ownerType": "Cluster",
    "ownerGVK": "hyperfleet.io/v1alpha1.Cluster"
  },
  ...
]
```

## Output: ledger.csv

The delivery ledger extends the registry with pipeline columns:

```csv
owner_type,field_path,write_mode,hidden,owner_gvk,feature_ref,test_ref,status,notes
Cluster,spec.deleteProtection,mutable,False,hyperfleet.io/v1alpha1.Cluster,,,needs-classification,
Cluster,spec.hostedCluster.autoNode,mutable,False,hyperfleet.io/v1alpha1.Cluster,,,needs-classification,
NodePool,spec.replicas,mutable,False,hyperfleet.io/v1alpha1.NodePool,,,needs-classification,
```

### Column Descriptions

| Column | Source | Populated By | Purpose |
|--------|--------|--------------|---------|
| `owner_type` | Field Registry | Stage 1 | Resource kind (Cluster, NodePool, etc.) |
| `field_path` | Field Registry | Stage 1 | JSONPath to field (spec.foo.bar) |
| `write_mode` | Field Registry | Stage 1 | Mutability: mutable, immutable, service-set |
| `hidden` | Field Registry | Stage 1 | Visibility: false=public, true=hidden |
| `owner_gvk` | Field Registry | Stage 1 | Full GVK (group/version.Kind) |
| `feature_ref` | **New** | Stage 3 | JIRA ticket (e.g., ROSA-1234) |
| `test_ref` | **New** | Stage 3 | Test case reference (e.g., e2e/create_cluster:foo) |
| `status` | **New** | Stage 3 | Delivery status (see below) |
| `notes` | **New** | Manual | Human annotations |

### Status Values

- `needs-classification` - Initial state (all rows start here)
- `passthrough-clean` - True passthrough, test exists (bulk delivery)
- `needs-test` - Passthrough but missing test
- `not-passthrough` - Requires conversion/defaulting (carved out)
- `delivered` - Shipped to production

## Pipeline Integration

### Stage 1: Ledger Builder (This Tool)
**Input:** `field_metadata.json`  
**Output:** `ledger.csv` with empty `feature_ref`, `test_ref`  
**Tool:** Deterministic (Python)

### Stage 2: Marker Suggester (Not Yet Implemented)
**Input:** `ledger.csv`  
**Output:** `ledger.csv` (no changes - markers already populated in field_metadata.json)  
**Tool:** AI-assisted (optional - markers already exist)

### Stage 3: Test Mapper (Not Yet Implemented)
**Input:** `ledger.csv` + existing v1 test suite  
**Output:** `ledger.csv` with `feature_ref`, `test_ref`, `status` populated  
**Tool:** AI-assisted mapping + deterministic verification

### Stage 4-7: Codegen → Translation → PR Orchestration
Read the ledger to drive batch code generation and delivery.

## FAQ

**Q: Why CSV instead of JSON?**  
A: CSVs are easy to review in spreadsheet tools (Google Sheets, Excel), support inline comments via the `notes` column, and work well with git diffs for tracking changes across pipeline stages.

**Q: Why not parse CRDs directly?**  
A: The Field Registry (`field_metadata.json`) already contains all fields with markers populated by `marker-scanner`. Parsing CRDs would duplicate work and lose the markers.

**Q: Can I edit the CSV manually?**  
A: Yes! The `notes` column is for manual annotations. However, `feature_ref`, `test_ref`, and `status` should be populated by Stage 3 (Test Mapper) to ensure consistency.

**Q: How often should I regenerate the ledger?**  
A: Regenerate whenever `field_metadata.json` changes (after adding new fields or updating markers). Run `make codegen-registry` first to update the registry, then `make accel-build-ledger`.
